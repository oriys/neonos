# 第 37 课：第一次从设备读到数据

状态：待开始。前置：[第 36 课](36-disk.md)。分 A、B、C 三次，每次 45～60 分钟。

## 目标与资料

使用现代 virtio-mmio、split queue 和一个在途请求读出探针标记。按 [Virtio 规范](https://docs.oasis-open.org/virtio/virtio/v1.2/virtio-v1.2.html) 的初始化、MMIO 和块设备章节实现；不混用旧版寄存器布局。

## A 次：设备与队列

1. 核对 magic、接口版本、块设备 ID 与容量，把真实 MMIO 页加入所有需要访问它的内核映射，保持 U=0。
2. 按规范完成 reset，然后设置 ACKNOWLEDGE、DRIVER，进行特性协商；现代 virtio 必须明确处理 `VIRTIO_F_VERSION_1`，只接受驱动真正实现的特性。设置 FEATURES_OK 后重新读取状态，确认设备没有清除该位。
3. 在 DRIVER_OK 之前完成 virtqueue 配置：选择队列、读取设备给出的最大队列长度、设置不超过上限的实际长度，为 descriptor、available、used 区及请求缓冲区分配满足规范对齐且生命周期稳定的内存，并把队列地址按现代 virtio-mmio 约定写给设备。
4. 队列和其他设备专用配置完成后，最后设置 DRIVER_OK；在 DRIVER_OK 之前不提交普通 I/O 请求。若初始化任一步失败，按规范设置 FAILED 或重新 reset，不把半初始化设备当作可用。
5. 核对交给设备的是物理地址，软件访问仍走可信内核映射。记录协商到的 flush 能力、容量和队列长度，先输出初始化摘要，不发请求。

记住初始化顺序：

```text
reset
  → ACKNOWLEDGE
  → DRIVER
  → feature negotiation
  → FEATURES_OK，并重新确认
  → 配置 virtqueue / device-specific state
  → DRIVER_OK
```

## B 次：一条读取请求

1. 构造请求头、数据区与状态字节的描述符链；读取时数据和状态由设备写入，方向位必须正确。
2. 发布描述符与 available 项，按平台要求完成内存顺序屏障后更新索引并通知设备；volatile 不能代替发布顺序。
3. 轮询 used ring，完成后按要求同步再读取返回状态与数据；校验返回描述符编号，不把任意索引变化当作当前请求成功。
4. 读取第 36 课探针位置，对比确切字节与校验值。virtio-blk 请求中的 `sector` 按设备协议单位解释，不等于本课程 4 KiB 文件系统块号；第 36 课的换算规则继续有效。
5. 第一版默认不用外部中断，但仍按设备要求处理可见性和完成状态；“used ring 变了”不等于设备状态一定为成功。

## C 次：范围、超时和复用

1. 检查扇区范围、请求长度与加法溢出；接近末尾的请求不能跨出容量。
2. 连续提交超过队列长度的请求，逐个完成再复用，验证描述符与索引不泄漏；索引回绕另用小模型核对。
3. 状态错误报告失败，不把缓冲区旧内容当有效读结果。
4. 超时后冻结请求与缓冲区，只有确认设备 reset 已使设备停止访问后才回收；无法确认则停止该设备路径并保留相关内存。超时本身不证明 DMA/设备访问已经结束。

## 常见问题与验收

| 现象 | 先检查 |
| --- | --- |
| FEATURES_OK 一设就消失 | 是否选择了设备不接受的特性，是否重新读取状态确认 |
| 队列配置完成但设备不工作 | DRIVER_OK 是否在全部队列配置完成之后设置 |
| 队列就绪但从不完成 | 队列地址、通知、特性及描述符方向 |
| 读到旧数据 | 是否检查完成状态和可见性顺序 |
| 读错 8 倍位置 | 是否把 512 字节设备 sector 和 4 KiB 文件系统 block 混用 |
| 超时后其他内存被改 | 是否过早复用了设备仍在访问的缓冲区 |

- [ ] 初始化状态顺序符合现代 virtio 要求，FEATURES_OK 经过回读确认，DRIVER_OK 最后设置。
- [ ] `VIRTIO_F_VERSION_1`、flush 能力和队列上限有真实协商记录。
- [ ] 初始化与标记读取成功，连续请求可复用。
- [ ] sector 与文件系统 block 的换算明确且测试通过。
- [ ] 越界、状态失败和超时有确定处理。
- [ ] 更新 [进度记录](progress.md)，注明暂用轮询完成。
