# 第 37 课：第一次从设备读到数据

状态：待开始。前置：[第 36 课](36-disk.md)。分 A、B、C 三次，每次 45～60 分钟。

## 目标与资料

使用现代 virtio-mmio、split queue 和一个在途请求读出探针标记。按 [Virtio 规范](https://docs.oasis-open.org/virtio/virtio/v1.2/virtio-v1.2.html) 的初始化、MMIO 和块设备章节实现；不混用旧版寄存器布局。

## A 次：设备与队列

1. 核对 magic、接口版本、块设备 ID 与容量，把真实 MMIO 页加入所有需要访问它的内核映射，保持 U=0。
2. 按规范完成 reset、确认驱动、特性协商、FEATURES_OK 检查和 DRIVER_OK；只接受已实现特性，现代版本特性与 flush 能力需明确记录。
3. 为 descriptor、available、used 区及请求缓冲区分配符合规范对齐的稳定页；初始化队列长度不得超过设备上限。
4. 核对交给设备的是物理地址，软件访问仍走可信内核映射。先输出初始化摘要，不发请求。

## B 次：一条读取请求

1. 构造请求头、数据区与状态字节的描述符链；读取时数据和状态由设备写入，方向位必须正确。
2. 发布描述符与 available 项，按平台要求完成内存顺序屏障后更新索引并通知设备；volatile 不能代替发布顺序。
3. 轮询 used ring，完成后按要求同步再读取返回状态与数据；校验返回描述符编号，不把任意索引变化当作当前请求成功。
4. 读取第 36 课探针位置，对比确切字节与校验值。第一版默认不用外部中断，但仍按设备要求处理待确认状态。

## C 次：范围、超时和复用

1. 检查扇区范围、请求长度与加法溢出；接近末尾的请求不能跨出容量。
2. 连续提交超过队列长度的请求，逐个完成再复用，验证描述符与索引不泄漏；索引回绕另用小模型核对。
3. 状态错误报告失败，不把缓冲区旧内容当有效读结果。
4. 超时后冻结请求与缓冲区，只有确认设备 reset 停止访问后才回收；无法确认则停止该设备路径并保留内存。

## 常见问题与验收

| 现象 | 先检查 |
| --- | --- |
| 队列就绪但从不完成 | 队列地址、通知、特性及描述符方向 |
| 读到旧数据 | 是否检查完成状态和可见性顺序 |
| 超时后其他内存被改 | 是否过早复用了设备仍在访问的缓冲区 |

- [ ] 初始化与标记读取成功，连续请求可复用。
- [ ] 越界、状态失败和超时有确定处理。
