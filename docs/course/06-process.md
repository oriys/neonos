# 第 06 课：程序与进程有什么区别

状态：待开始。前置：[第一阶段](stage-01.md) 验收完成。预计 45～60 分钟。

## 目标与阅读

把“磁盘或镜像里的一段程序”与“这次运行的记录”分开。阅读 [OSTEP 第 4 章 Processes](https://pages.cs.wisc.edu/~remzi/OSTEP/)，关注进程保存哪些信息、哪些状态可以变化；第 5 章先认识接口目的，不要求此时实现 `fork`。

## 代码导读（10 分钟）

回看 `rust_main`：现在它只运行内核自身代码。第一阶段的 `TrapFrame` 记录 CPU 某一时刻的现场，但进程还需要身份、状态和资源范围等信息。

用“同一份菜谱可以做两次菜”理解：程序是静态描述，进程是某一次执行。本课还不进入用户态。

## 分步实验（30 分钟）

1. 创建计划中的 `src/process.rs`，定义 `Program`：名称、入口地址、代码范围。入口必须来自已链接的符号，不能凭空填一个地址。
2. 定义 `Process`：运行编号、所用程序、状态、用户栈范围、用户陷入时使用的内核栈范围、保存现场的位置。资源尚未准备时用显式的未初始化状态或 `Option` 表示，不伪造可用指针。
3. 用 Rust `enum` 表示 `Ready`、`Running`、`Exited(code)`、`Faulted(cause)`。本阶段无阻塞操作，`Blocked` 只画在扩展状态图中，后续再实现。
4. 使用一个固定记录槽位，手工模拟 `Ready → Running → Exited(0)`；打印每次变化。明确标记为状态模拟，尚未执行用户指令。
5. 模拟第二次运行：使用相同的程序描述，赋予不同运行编号，重新初始化记录。
6. 尝试把已退出记录直接变为 `Running`，设计成返回错误；只有明确重置成新实例后才能再次运行。

不要为练习引入全局可变引用。先由一个管理函数持有并修改记录，CPU 陷入后如何取得当前实例留给后续课接入。

## 预期结果与常见问题

应看到两次独立编号的状态变化，不能把它写成“两次用户程序运行成功”。

| 问题 | 提示 |
| --- | --- |
| 程序结构里全是会变的字段 | 入口与名称属于描述，寄存器与退出码属于运行实例 |
| `Exited` 后还能直接运行 | 状态转换是否集中处理并检查合法性 |
| 想先实现就绪队列 | 本阶段只需要一个记录槽，队列属于第三阶段 |

## 验收与复盘（10 分钟）

- [ ] 用自己的话区分程序、进程和现场记录。
- [ ] 两次模拟实例编号不同，程序描述可复用。
- [ ] 非法状态转换被拒绝，已有启动输出仍正常。
- [ ] 能画出当前状态图，并指出何时才需要等待状态。
- [ ] 更新 [进度记录](progress.md)，注明本课是数据模型实验。

小练习：解释退出码应该属于程序描述还是运行实例。
