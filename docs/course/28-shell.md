# 第 28 课：终于可以输入命令了

状态：待开始。前置：[第 27 课](27-pipes.md)。分 A、B、C 三次，每次 45～60 分钟。

## 目标与范围

实现真正运行于用户态的小 shell，内核只提供输入输出和进程服务。支持内建 `help`、`exit`，内嵌外部程序 `hello`、`cat`，以及一个 `|` 连接的两段管道。不支持参数、引号、后台运行或文件重定向；遇到这些输入明确提示范围。

## A 次：串口输入与行缓冲

1. 在控制台模块接入 UART 接收状态检查和单字节读取，按当前 QEMU UART 设备资料核对寄存器，不能无限读取空接收寄存器。
2. 第一版用内核定时轮询接收并放入固定环形缓冲；read(0) 无数据时按第 25 课模型 Blocked。定时事件或其他内核安全入口轮询后唤醒读者。
3. 扩展空闲路径：所有任务 Blocked 时仍保留可返回的 S 模式定时处理入口，在安全调度栈等待或短轮询，不能关闭所有事件后永远停住。只在入口、栈和等待状态就绪后开放所需中断。
4. 用户态 shell 使用固定 128 字节行缓冲，支持回车、换行、退格与空行。超长行丢弃到行尾后提示错误；一次 CRLF 不重复执行命令。
5. 样例先用已有整数汇编、用户栈和系统调用实现有界状态机，字符串表和内部引用遵守第四阶段镜像复制约定。

每次约 15 分钟概念、30 分钟接入、15 分钟验证。回显只由一个层次负责，避免每个字符出现两遍。

## B 次：fork、exec、wait 串起来

1. shell 把有限命令名映射到内嵌 program_id；help 直接列出命令，未知命令不创建子进程。
2. 外部命令：fork；子执行 exec；exec 失败打印错误并显式 exit；父 wait 指定子 PID，完成后重新提示。
3. hello 通过 fd 1 输出固定问候语；cat 从 fd 0 反复读并写到 fd 1，正确处理部分写入。
4. 本课交互控制台不定义 Ctrl-D EOF，裸 cat 会持续等待；主要通过管道让 cat 收到 EOF，help 中写明这一点。shell 的 exit 结束用户 shell，由内核管理者回收并输出会话结束标记。
5. 验证未知命令、资源不足、子程序失败与重复正常命令，提示符都按预期出现。

## C 次：实现 hello | cat

1. shell 先解析两侧且只允许一个管道符，空侧或未知命令在分配资源前拒绝。
2. 创建管道后 fork 左子：dup2 写端到 fd 1，关闭原读写 fd，exec hello。
3. fork 右子：dup2 读端到 fd 0，关闭原读写 fd，exec cat。
4. 父在两个子创建后关闭自己的读写端，再等待两个 PID。必须先创建消费者，不能先等生产者结束，否则大输出可能填满管道后死锁。
5. 第二次 fork 失败时父关闭全部管道端；已创建生产者会得到无读者错误并退出，父仍须 wait 它。用户样例必须检查 write 错误，不能永远重试。
6. 两个孩子都回收后打印提示符。可临时将生产者改成输出超过管道容量的固定内容，验证并非靠小数据侥幸通过。

## 常见问题与总验收

| 现象 | 先检查 |
| --- | --- |
| shell 等输入后再也不醒 | 空闲状态下定时轮询和 S 模式返回入口是否有效 |
| 管道显示内容但不出提示符 | 多余写端是否未关闭，是否等待了两个孩子 |
| 子 exec 失败又出现一个 shell | 子错误分支是否忘了退出 |
| 大数据管道才卡住 | 是否在创建消费者前等待生产者 |
