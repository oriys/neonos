# 第 00 课：开始之前，先认识这台“电脑”

状态：预备课。建议 2～4 次，每次 45～60 分钟。目标不是先学完整门 Rust、汇编或计算机组成，而是建立后续课程反复使用的最小概念地图。

## 为什么需要这一课

第 01～04 课可以边做边认识工具，但从第 05 课开始会连续出现寄存器、ABI、CSR、链接符号、裸指针和异常现场。如果这些词完全没有位置感，学习者容易把“不会术语”误认为“不会操作系统”。本课只回答：这些东西分别属于哪一层、遇到时去哪查。

## 00A：CPU、内存、地址和十六进制

先建立四个概念：

- CPU：按指令一步步执行；当前课程只使用一个 RISC-V hart。
- 寄存器：CPU 内部很小但很快的临时存储；函数调用和异常处理都会用到。
- 内存：按字节编号的大空间；编号就是地址。
- 十六进制：只是数字写法。`0x1000_0000` 和十进制数字一样都表示一个数，底层课程常用它是因为和二进制边界更容易对应。

纸上练习：把 `0x1000`、`0x1004`、`0x2000` 看成三个地址，解释相差多少字节；不要求手算复杂进制转换。

## 00B：只认识后面最常见的 RISC-V 寄存器

先记用途，不背全部 32 个名字：

| 名称 | 先这样理解 |
| --- | --- |
| `sp` | 当前栈顶 |
| `ra` | 普通函数返回地址 |
| `a0`～`a7` | 函数参数、返回值；课程也用它们传系统调用参数 |
| `t0`～`t6` | 临时寄存器，调用者不能假设函数返回后还保持原值 |
| `s0`～`s11` | 被调用者保存寄存器，普通 ABI 约定要求被调用函数恢复 |
| `x0` | 永远读为 0 |

第一次看到以下指令时只理解动作：

```text
la      取得某个链接符号的地址
call    调用函数
ret     返回普通函数调用者
j       无条件跳转
wfi     等待中断/事件的提示性指令
```

后续遇到 `csrr/csrw/sret/sfence.vma` 再在对应课程学习，不提前背。

## 00C：ABI 是什么

ABI 可以先理解为“两个编译好的代码片段如何约定合作”。例如普通 RISC-V 函数调用会约定：参数放哪里、返回值放哪里、哪些寄存器由谁保存、调用时栈怎样对齐。

这解释了为什么课程不能随便从汇编跳进一个 Rust 函数：如果没有满足 ABI，Rust 编译器生成的代码就没有理由正确运行。

## 00D：Rust 只准备这些概念

课程使用 `#![no_std]`，但不要求先学完整 Rust。开始前只认识：

- `fn`：函数。
- `const`：编译期常量。
- `&T`：借用一个值，不等于复制整个值。
- `*const T` / `*mut T`：裸指针，只是地址加类型信息；解引用需要额外安全保证。
- `unsafe`：表示编译器无法替你证明某些条件，不表示里面的代码可以随便写。
- `Option<T>`：有值或没有值。
- `Result<T, E>`：成功结果或错误。
- `enum`：一组互斥状态，例如 `Ready/Running/Exited`。

后面的 trait、宏、原子类型、所有权细节按课程第一次使用时再学。

## 00E：ELF、section 和 linker 先放到同一张图里

Rust 编译完成后不是直接得到“内存已经摆好的程序”。链接器会按照 `linker.ld` 把不同内容放到不同区域：

```text
.text      机器指令
.rodata    只读数据
.data      有初值的可写数据
.bss       启动后应为零的可写数据
```

`ENTRY(_start)` 告诉链接结果的入口符号；`. = 0x80200000` 一类表达式决定地址布局。第 04 课再真正测量这些区域。

## 00F：QEMU、OpenSBI、内核分别是谁

当前项目启动链先这样记：

```text
宿主机 macOS/Linux
  ↓ 运行 qemu-system-riscv64
QEMU virt 虚拟机器
  ↓
OpenSBI 固件
  ↓
neonos 的 _start
  ↓
rust_main
```

OpenSBI 不是 neonos，也不是用户程序。后续定时器课程会让内核通过 SBI 请求固件提供服务。

## 00G：开发环境检查

至少确认：

```sh
rustc --version
cargo --version
qemu-system-riscv64 --version
rustup target list --installed
```

项目需要 Rust 的 `riscv64gc-unknown-none-elf` 目标和 `qemu-system-riscv64`。缺失时先按各自官方安装方式补齐，再运行：

```sh
cargo build
./tests/boot.sh
```

不要为了“让测试过”修改内核目标或测试脚本。环境错误和课程代码错误要分开处理。

## 预备课验收

完成后不要求能独立写汇编，但应能回答：

- [ ] CPU、寄存器、内存、地址分别是什么。
- [ ] `sp`、`ra`、`a0` 至少各自做什么。
- [ ] 为什么汇编调用 Rust 也需要遵守 ABI。
- [ ] `unsafe` 为什么不是“关闭安全检查后随便写”。
- [ ] `.text/.data/.bss` 大致保存什么。
- [ ] 能画出 QEMU → OpenSBI → `_start` → `rust_main`。
- [ ] `cargo build` 与 `./tests/boot.sh` 在当前机器可以执行；如果失败，记录的是环境问题还是代码问题。

通过后进入 [第 01 课：从开机到 Hello kernel](01-boot.md)。后续忘记这些概念时随时回来查，不需要一次背完。
