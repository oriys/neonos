# 第 00 课：开始之前，先认识这台“电脑”

状态：预备课。建议拆成 3 次，每次 45～60 分钟。目标不是先学完 Rust、汇编或计算机组成，而是建立后续课程反复使用的最小概念地图，并把开发环境验证到可用状态。

> 本课最重要的规则：**理解“它属于哪一层、解决什么问题”即可，不背寄存器表，不背指令，不背十六进制转换。** 后续第一次真正使用时还会重新讲。

## 为什么需要这一课

第 01～04 课可以边做边认识工具，但从第 05 课开始会连续出现寄存器、ABI、CSR、链接符号、裸指针和异常现场。如果这些词完全没有位置感，很容易把“暂时不认识术语”误认为“不会操作系统”。

本课先回答四个问题：

1. 我们写的内核到底运行在哪台“机器”上？
2. CPU、寄存器、内存和地址是什么关系？
3. Rust 源码怎样变成 QEMU 能启动的内核？
4. 开始第 01 课前，本机环境是否真的准备好了？

## 第一次：宿主机、QEMU、CPU、内存

### 00A：先分清两台“电脑”

课程里同时存在两层机器：

```text
你的真实电脑（宿主机，macOS/Linux）
  │
  │ 运行 qemu-system-riscv64
  ↓
QEMU 模拟出来的 RISC-V virt 机器（实验机）
  │
  └─ neonos 真正运行在这里
```

所以：

- `cargo`、编辑器、Git、Python 脚本运行在宿主机。
- neonos 内核编译成 RISC-V 指令后，不能直接在普通 x86_64/Apple Silicon 宿主机上运行。
- `cargo run` 会通过项目配置启动 QEMU，再让 QEMU 运行内核。

**小检查：** 如果你在 Apple Silicon Mac 上开发，为什么 neonos 仍然可以执行 RISC-V 指令？

### 00B：CPU、寄存器、内存、地址

先建立四个概念：

- **CPU**：不断取出并执行机器指令。当前课程只使用一个 RISC-V hart，可以先理解成一个 CPU 执行核心。
- **寄存器**：CPU 内部少量、非常直接的工作位置，函数调用和异常处理都会使用。
- **内存**：可以先想成一长排按字节编号的格子。
- **地址**：某个内存位置的编号。

例如：

```text
地址          里面的一个字节
0x1000  →     ??
0x1001  →     ??
0x1002  →     ??
0x1003  →     ??
0x1004  →     ??
```

因此 `0x1000` 到 `0x1004` 相差 **4 个字节地址**。这里的 `0x` 只表示数字使用十六进制写法。

为什么底层代码爱写十六进制？因为像 `0x1000`、`0x2000`、`0x1000_0000` 这样的边界，比很长的十进制数字更容易辨认。现在不需要练复杂进制转换。

**小练习：**

1. `0x2000` 和 `0x2001` 相差几个字节？
2. 一个 `u8` 是 1 字节。如果某设备寄存器位于 `0x1000_0000`，向这个地址写一个 `u8`，最直观可以理解为写了多少字节？

### 00C：只认识后面最常见的寄存器

先记用途，不背全部 32 个整数寄存器：

| 名称 | 先这样理解 |
| --- | --- |
| `sp` | stack pointer，当前栈顶 |
| `ra` | return address，普通函数返回地址 |
| `a0`～`a7` | 函数参数/返回值；课程也会用它们传系统调用参数 |
| `t0`～`t6` | 临时寄存器 |
| `s0`～`s11` | 按普通 ABI 约定需要被调用函数保存/恢复的一组寄存器 |
| `x0` | 永远读为 0 |

本阶段第一次看到下面的汇编，只理解动作：

```text
la      取得一个符号对应的地址
call    调用函数
ret     从普通函数返回
j       无条件跳转
wfi     告诉处理器当前可以等待；程序仍需用控制流保证不会意外继续到未知代码
```

后续遇到 `csrr`、`csrw`、`sret`、`sfence.vma` 时，会在对应课程重新解释。

## 第二次：Rust、ABI、ELF 和启动链

### 00D：ABI 是“合作规则”

ABI（Application Binary Interface）可以先理解为：**已经编译成机器指令的两段代码怎样约定合作。**

普通 RISC-V 函数调用至少需要约定：

- 参数放在哪些寄存器；
- 返回值放哪里；
- 哪些寄存器由调用者负责保存；
- 哪些寄存器由被调用者负责恢复；
- 调用 Rust 函数时栈需要满足什么对齐要求。

所以“汇编能跳到 Rust 函数地址”不等于“Rust 函数一定能正常运行”。后面写 trap 和上下文切换时，我们会反复依赖这条规则。

### 00E：本课程最先遇到的 Rust 概念

第 01 课只需要先认识：

- `fn`：函数。
- `const`：常量。
- `&T`：对现有值的引用；第一次真正使用会在第 02 课展开。
- `*const T` / `*mut T`：裸指针，可以先理解为“带类型信息的地址”。
- `unsafe`：表示有些安全条件需要程序员自己保证，**不是**“这段代码可以随便写”。
- `#![no_std]`：这个 crate 不链接 Rust 标准库 `std`；仍然可以使用更底层的 `core`。
- `#![no_main]`：不使用普通 Rust 应用程序的 `main` 启动入口，项目自己提供 `_start`。

`Option`、`Result`、`enum`、trait、宏、原子类型等，都等第一次真正需要时再学，不要求在第 00 课提前背。

### 00F：源码怎样变成内核

先把编译和启动分成两条链：

```text
构建：
Rust / 汇编源码
  ↓ rustc + linker
RISC-V ELF 文件

运行：
QEMU virt
  ↓
OpenSBI 固件
  ↓
neonos 的 _start
  ↓
rust_main
```

ELF 可以先理解为“包含机器指令、数据、入口和布局信息的可执行文件格式”。链接器会按照 `linker.ld` 把不同内容放到不同区域：

```text
.text      机器指令
.rodata    只读数据
.data      有初值的可写数据
.bss       运行时需要空间、按约定初始化的可写数据
```

`ENTRY(_start)` 把 `_start` 指定为 ELF 入口；项目当前从 `0x80200000` 开始安排内核镜像。第 04 课再真正测量各区域，不需要现在掌握链接脚本语法。

### 00G：QEMU、OpenSBI、neonos 分别是谁

当前项目启动链先这样记：

```text
宿主机
  ↓ 启动 qemu-system-riscv64
QEMU virt 虚拟机器
  ↓ 先执行固件
OpenSBI
  ↓ 把控制权交给内核入口
neonos::_start
  ↓ 准备最早期运行环境
rust_main
```

OpenSBI 不是 neonos，也不是用户程序。第 13 课会看到 neonos 反过来通过 SBI 向固件请求定时器服务。

**小检查：** `_start` 和 `rust_main` 都属于 neonos，为什么还需要两个入口层次？先给出自己的猜测即可，第 01 课会验证。

## 第三次：把开发环境验证到真的可用

### 00H：检查工具是否存在

在项目根目录依次运行：

```sh
rustc --version
cargo --version
qemu-system-riscv64 --version
rustup target list --installed
command -v file
```

项目默认目标是：

```text
riscv64gc-unknown-none-elf
```

如果 `rustup target list --installed` 中没有它，可执行：

```sh
rustup target add riscv64gc-unknown-none-elf
```

如果系统找不到 `qemu-system-riscv64`，先按 QEMU 或所用操作系统包管理器的官方安装说明安装 QEMU，再回来继续。不要为了绕过环境问题修改项目 target、删掉启动测试或换成本机目标。

`tests/boot.sh` 还会使用普通 shell 工具（例如 `file`、`grep`、`mktemp`、`sleep`）。如果脚本报告某个命令不存在，把它记为宿主机环境问题，而不是内核逻辑问题。

### 00I：第一次构建与启动检查

先只编译：

```sh
cargo build
```

成功表示“Rust 源码可以编译并链接成当前 RISC-V ELF”，**不等于内核已经成功启动**。

再运行：

```sh
./tests/boot.sh
```

这个脚本会构建内核、启动 QEMU，并等待日志里出现 `Hello kernel`。成功时可以说明当前仓库至少已经走通：

```text
构建 → 链接 → QEMU → OpenSBI → _start → rust_main → UART 输出
```

但它只检查现有的 `Hello kernel` 标记，不证明未来新增的 panic、分页、调度等功能也正确。

### 00J：学会记录“哪一层坏了”

如果失败，不要第一反应就是改代码。先按层次分类：

| 现象 | 更可能先检查哪一层 |
| --- | --- |
| `cargo: command not found` | 宿主机 Rust/Cargo 环境 |
| target 缺少 `core` | Rust RISC-V target |
| `qemu-system-riscv64: not found` | QEMU 安装/PATH |
| 编译成功，但只有 OpenSBI 输出 | 内核加载、入口、UART 路径 |
| `Hello kernel` 出现 | 当前最小启动链已经成功 |

这张表以后会不断扩展成真正的 OS 调试思路：**先定位层，再定位代码。**

### 参考答案只在检查后看

<details>
<summary>两个小检查的参考思路</summary>

1. Apple Silicon/x86_64 宿主机不需要直接执行 RISC-V 指令；QEMU 模拟了 RISC-V 实验机，neonos 在模拟机里执行。
2. `_start` 负责最早期、Rust 普通函数还不能假设已经具备的环境准备，例如设置栈；准备好以后再按 ABI 调用 `rust_main`。

</details>
