# 第 16 课：同一个地址，能住不同的数据吗

状态：待开始。前置：[第三阶段](stage-03.md) 验收完成。预计 45～60 分钟。

## 为什么现在才引入虚拟地址

前三阶段虽然有多个 Process，但它们仍在同一个裸地址世界里：

```text
任务 A 的“地址 0x...”
任务 B 的“地址 0x...”
```

本质上都指向同一套实际物理地址解释。

独立用户栈只是“大家约定使用不同区域”，并不是 CPU 强制隔离。

第四阶段要实现真正的地址翻译，让：

```text
Process A: VA 0x01000000 → PA X
Process B: VA 0x01000000 → PA Y
```

两个进程看到**相同虚拟地址数值**，却保存不同数据。

阅读 OSTEP 第 13、15 章；选读第 16 章分段，只理解虚拟化动机，不在本课实现页表。

## 本课只先固定 4 KiB 页

```text
page size = 4096 bytes = 0x1000
```

一个地址可以拆成：

```text
page number | offset inside page
```

对 4 KiB 页：

```text
offset = address 的低 12 位
page number = address >> 12
```

因为：

```text
2^12 = 4096
```

不需要先背二进制，只要会用边界例子验证。

## 先做 5 个边界例子

| 地址 | 页号变化 | 页内 offset |
| --- | --- | ---: |
| `0x0000` | 第 0 页 | 0 |
| `0x0fff` | 第 0 页最后一字节 | 4095 |
| `0x1000` | 下一页 | 0 |
| `0x1001` | 下一页 | 1 |
| `0x1fff` | 第 1 页最后一字节 | 4095 |

如果这里还不能稳定解释，先不要进入 Sv39。

## 一个完整地址翻译例子

假设页表告诉我们：

```text
虚拟页 0x00400000
→ 物理页 0x81000000
```

访问：

```text
VA = 0x00400123
```

页内 offset 是：

```text
0x123
```

因此：

```text
PA = 0x81000000 + 0x123
   = 0x81000123
```

现在让另一个进程把同一个虚拟页映射到：

```text
0x82000000
```

同一个 VA `0x00400123` 就会得到不同 PA。

这些是纸上算例，不表示这些物理页已经被第 17 课分配器认定为可用。

## 地址“有效”和“允许访问”是两个问题

后面页表查询会至少回答两层：

```text
1. 这个 VA 有没有映射到某个 PA？
2. 当前访问者有没有 R/W/X/U 权限？
```

所以：

```text
地址落在“看起来像用户区”的数字范围
≠ 一定有映射
≠ 一定允许读
≠ 一定允许写
```

第 22 课会靠这个原则验证用户指针。

## 先区分类型，避免全项目都是 usize

在内存模块中引入轻量 newtype/包装类型，至少概念上区分：

```text
PhysAddr
VirtAddr
PhysPageNum / FrameNum
VirtPageNum
```

目标不是炫技，而是让错误更显眼：

```text
map(vpn, ppn)
```

比：

```text
map(usize, usize)
```

更难把两边参数写反。

本课不要求实现复杂 trait 运算；先保证构造、取值、对齐函数清楚。

## 三个基础运算

### 向下对齐

```text
align_down(addr, 4096)
```

例：

```text
0x1234 → 0x1000
```

### 检查式向上对齐

```text
align_up(addr, 4096)
```

例：

```text
0x1000 → 0x1000
0x1001 → 0x2000
```

接近整数上限时，`addr + 4095` 可能溢出，所以不能只写一个会静默回绕的表达式；使用 checked arithmetic，失败返回明确错误。

### 页内 offset

```text
offset = addr & 0xfff
```

验证：

```text
0
4095
4096
4097
```

## 常见问题

| 误解 | 修正 |
| --- | --- |
| 页号就是页起始地址 | 页号需要乘 4096/左移 12 位才得到页基址 |
| VA 数字更小，所以物理内存也更靠前 | VA/PA 是两个地址空间中的编号，映射决定关系 |
| 地址在用户范围就一定能访问 | 还需要有效映射和权限检查 |
| `align_up` 永远不会失败 | 接近整数上限可能溢出 |
| MMIO 也可以拿来当普通 RAM frame | MMIO 地址空间不是可自由分配 RAM |
