# 第 16 课：同一个地址，能住不同的数据吗

状态：待开始。前置：[第三阶段](stage-03.md) 验收完成。预计 45～60 分钟。

## 目标与阅读

阅读 OSTEP 第 13、15 章，选读第 16 章分段。先区分物理内存中的位置与程序使用的地址，再理解地址转换为何有用。[官方章节入口](https://pages.cs.wisc.edu/~remzi/OSTEP/)

## 导读与纸上实验（20 分钟）

回看第一阶段 `linker.ld` 的段边界，以及第三阶段各任务的栈范围。此前任务使用同一个物理地址空间；独立栈只是使用不同区域，还没有页表访问隔离。

把 4 KiB 内存页想成编号的箱子，页内偏移是箱内的位置。假设虚拟页 `0x00400000` 映射到物理页 `0x81000000`，那么虚拟地址 `0x00400123` 对应物理地址 `0x81000123`。这是算例，不表示该物理页已可供实际使用。

再让另一个进程把同一虚拟页映射到不同物理页，手算同一个偏移的新结果。

## 分步练习（25 分钟）

1. 绘制当前 RAM、固件、内核、栈、MMIO 的实际范围；RAM 范围以实验机配置和设备树为准。
2. 画出未来用户代码、私有数据、用户栈、保护页和内核区域，采用 [阶段布局](stage-04.md) 中不冲突的地址。
3. 在内存模块定义轻量的 `PhysAddr`、`VirtAddr`、物理页号和虚拟页号类型，让混用在接口上更显眼。
4. 编写或手算页内偏移、向下对齐、检查式向上对齐；覆盖 `0`、`4095`、`4096`、`4097` 与接近地址上限的值。加法溢出应返回错误。
5. 思考“地址有效”与“该进程被允许读写”是不同检查。

## 常见问题与验收

| 问题 | 提示 |
| --- | --- |
| 页号直接当地址 | 页号需要乘页大小，再加偏移 |
| 所有地址都用一个整数类型 | 调用点很难发现虚拟地址和物理地址混用 |
| 向上对齐得到零 | 是否发生整数回绕 |

- [ ] 对齐边界和溢出处理明确，更新 [进度记录](progress.md)。
