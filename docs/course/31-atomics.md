# 第 31 课：原子操作能保护什么

状态：待开始。前置：[第 30 课](30-threads.md)。分 A、B 两次，每次 45～60 分钟。

## 目标与阅读

阅读 OSTEP 第 28～29 章。用 [Rust 原子排序文档](https://doc.rust-lang.org/core/sync/atomic/enum.Ordering.html) 查 Acquire、Release 与 Relaxed 的用途。本课不要求掌握所有弱内存模型细节。

## A 次：从单计数到复合不变量

1. 复盘第 29 课 fetch_add；再构造两个账户间转移的逐步模拟，解释单个字段原子不保证两个字段同时完成更新。
2. 在宿主机先用标准 Mutex 保护整个转移操作，并让读取总额也取得同一把锁；始终验证总额守恒。
3. 手算 compare-exchange 获取锁的成功与失败分支。成功 Acquire、释放 Release，保证受保护数据的可见性；不把 volatile 当同步原语。
4. 自制原子锁先只保护实验中的原子字段或模拟状态，不随手对任意类型实现 `unsafe Sync` 来绕过编译器。

## B 次：自旋、中断与单核

1. 区分用户自旋锁和内核短临界区。用户持锁者被抢占后可能恢复；若内核关中断后自旋等待同核另一个任务，持锁者就无法运行。
2. 用事件轨迹展示“任务持锁→中断处理器取同一把锁”的停滞，不在正常内核启动路径故意永久自旋。
3. 审计内核临界区：保持短小，不打印、不分配、不调度、不睡眠。保存原中断状态并按嵌套规则恢复，不能退出临界区时一律开中断。
4. 同步保护范围要覆盖所有访问者，包括中断路径；关本地中断只是当前单核模型的互斥条件，不是未来多核锁。
5. 记录自旋尝试次数与完成结果，对比下一课的 Blocked 行为。调度器本身需要的保护不能反过来依赖睡眠调度。

## 常见问题与验收

| 现象 | 先检查 |
| --- | --- |
| 总额观察不守恒 | 读取者是否绕过同一保护范围 |
| 自旋直到超时 | 持锁者是否还有机会获得 CPU |
| 离开内层临界区后突然中断 | 是否错误恢复了原状态 |
