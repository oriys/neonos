# 第 40 课：约定磁盘上每个区域的含义

状态：待开始。前置：[第 39 课](39-cache.md)。分 A、B 两次，每次 45～60 分钟。

## 目标与阅读

阅读 OSTEP 第 40 章。采用 [阶段固定布局](stage-07.md)，用宿主机工具格式化全新专用镜像，让内核挂载并核对相同格式。

## A 次：先写格式说明

1. 创建计划中的 `docs/fs-format.md`，明确魔数、版本、每个字段的字节宽度、偏移、端序、边界和保留位要求。
2. inode 固定 64 字节：类型 u32、大小 u32、12 个 u32 直接块号、8 字节保留零。块号 0 表示未分配；当前文件最大 49152 字节。
3. 目录项固定 64 字节：inode 号 u32、名称长度 u16、类型 u8、保留 u8、56 字节名称；空项 inode=0，名称按长度读取，不要求末尾零。
4. 宿主机 `tools/mkfs.py` 显式编码格式，初始化位图、根 inode 与根目录块，默认不覆盖已有文件。根目录初始大小可为 0，但块 21 已归它持有。
5. 用独立解码打印超级块与根信息，不只依靠写入函数自己宣称成功。

## B 次：挂载与位图

1. 内核只挂载匹配格式，检查块大小、容量、各区域无重叠、根 inode 合法和引用块在范围内。
2. 魔数或布局损坏时报告并拒绝挂载，不自动格式化未知镜像。
3. 分配只搜索数据区空闲位，inode 跳过 0 和根；写回时同时维护内存状态与脏标记。
4. 块重用前清零；区间外、保留块与重复释放应拒绝。尚无删除接口，释放主要用于失败回滚与测试。
5. 在小测试可用区模拟耗尽，再恢复并 sync，重启核对位图。

## 常见问题与验收

| 现象 | 先检查 |
| --- | --- |
| 宿主机正常，内核读错 | 字段偏移和端序是否统一 |
| 分配覆盖超级块 | 位图保留位及搜索起点是否正确 |
| 坏镜像被重置了 | 挂载失败是否误走格式化路径 |

- [ ] 格式文档、生成器、内核解码一致。
- [ ] 布局校验和分配边界正确，坏镜像拒绝且保持原样。
- [ ] 更新 [进度记录](progress.md)。
