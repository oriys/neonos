# 第 38 课：写完了，真的保存了吗

状态：待开始。前置：[第 37 课](37-block-read.md)。分 A、B 两次，每次 45～60 分钟。

## A 次：写入和回读

1. 复用请求队列，按写请求调整类型和方向，写入已选定的探针区域。数据在完成前保持不变。
2. 等待设备完成并检查状态；另提交读取到不同缓冲区，比较长度、字节和校验值。
3. 测试相邻扇区不同模式，证明没有把请求号、扇区和字节偏移混淆。
4. 以只读后端或受控驱动失败注入测试错误，明确成功字节与失败状态，不能输出虚假的成功标记。

## B 次：刷新后再启动

1. 确认已协商 flush，按 [Virtio 块设备规范](https://docs.oasis-open.org/virtio/virtio/v1.2/virtio-v1.2.html) 提交刷新并等待成功，不把它实现成空函数。
2. 记录 QEMU 后端缓存配置，禁止用忽略 flush 的不安全模式进行持久化验收。
3. 来宾写入新标记并 flush，正常结束 QEMU；启动同一镜像，只读核对标记。脚本不能在第二次启动前重新创建镜像。
4. 分别记录“设备写完成”“flush 完成”“重启读取成功”。这证明本实验配置下的路径，不等于真实硬件断电保证。
5. 写入或 flush 状态不确定时停止后续写操作，保留诊断，不在原位置盲目重试多步骤元数据更新。

每次约 10 分钟说明、30 分钟实验、15 分钟复盘。

## 常见问题与验收

| 现象 | 先检查 |
| --- | --- |
| 同次运行能读，重启没内容 | flush、镜像路径和后端配置 |
| 重启后变回初始探针 | 启动脚本是否重新生成磁盘 |
| 写只读盘却报告成功 | 是否检查设备状态和协商特性 |

- [ ] 写读一致，相邻区域无串写。
- [ ] flush 与重启验收各有真实记录，失败不当成功。
- [ ] 更新 [进度记录](progress.md)。
