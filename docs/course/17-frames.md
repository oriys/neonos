# 第 17 课：管理可用的物理页

状态：待开始。前置：[第 16 课](16-addresses.md)。分 A、B 两次，每次 45～60 分钟。

## 目标与导读

建立按 4 KiB 分配和回收的物理页分配器。复习 OSTEP 第 17 章空闲空间管理；本课分配固定大小页，第 18 课才处理不同大小对象。

## A 次：先知道哪些页能用

1. 从实际 QEMU 配置、设备树和固件信息核对 RAM；保留内核镜像、所有静态栈、分配器元数据、固定堆 arena、仍需使用的设备树及其他预留内存。
2. 对可用区间向内页对齐，避免把边缘的一部分预留页分配出去；MMIO 不是 RAM。
3. 在计划中的 `src/memory/frame.rs` 用固定容量位图或页状态表记录 Reserved、Free、Allocated。元数据本身先静态预留，不能靠尚未可用的分配器分配自身。
4. `alloc_frame` 从 Free 页取得唯一所有权，失败返回 `None` 或明确错误，不返回零地址充数。
5. 连续分配若干页，打印范围与分配前后空闲数，验证地址对齐、不重复、不进入预留区。

前 15 分钟核对布局，中间 25 分钟实现状态转换，最后 15 分钟检查结果。先关闭定时器运行这些实验。

## B 次：耗尽、归还与重用

1. 给释放接口定义所有权要求：只有当前仍被分配、且不再被任何映射或使用者持有的页才可释放。
2. 拒绝未对齐地址、区间外页、预留页和重复释放；错误不能改变计数。
3. 在小型测试池里分配到耗尽，再释放一个并重新分配；不要耗尽内核后续启动需要的全部 RAM。
4. 重用前清零，尤其是将要交给用户的页。用非零探针证明拿到的新页不泄露上一使用者的数据。
5. 对比起始与结束空闲数；明确物理页分配器不是引用计数器，不自动知道页表是否还引用某页。

为这些所有权行为编写有意义的检查，而不只测试一个已知地址能返回。

## 常见问题与验收

| 现象 | 先检查 |
| --- | --- |
| 分配后内核代码损坏 | 预留范围是否含全部镜像和元数据 |
| 释放后空闲数变多两次 | 是否检测重复释放 |
| 新用户页出现旧数据 | 是否在交付前清零 |

- [ ] 有机器范围依据和预留清单。
- [ ] 唯一性、耗尽、非法释放与重用清零通过。
- [ ] 完整分配释放后统计恢复，原启动正常。
- [ ] 更新 [进度记录](progress.md)。
