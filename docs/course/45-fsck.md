# 第 45 课：让检查器指出磁盘哪里不一致

状态：待开始。前置：[第 44 课](44-crash-consistency.md)。分 A、B 两次，每次 45～60 分钟。

## 目标

实现一个宿主机只读检查器 `tools/fsck.py`。它不依赖内核运行，也不自动修复磁盘；它直接按照 `docs/fs-format.md` 解码镜像，并把违反文件系统不变量的位置说清楚。

## A 次：先完整扫描

1. 读取并校验超级块：魔数、版本、块大小、总块数、区域边界和根 inode。
2. 读取块位图与 inode 位图，建立“声明已占用”的集合。
3. 遍历所有已分配 inode：验证类型、大小、直接块号范围和最大文件大小。
4. 遍历目录项：验证名称长度、类型、inode 号范围和目标 inode 已分配。
5. 建立“实际被引用的数据块”集合，并记录引用来源，例如 `inode 7 direct[2]`。

检查器遇到一个错误后继续扫描其他独立区域，最后按错误类别汇总；但如果超级块本身无法安全确定边界，应停止深度扫描，避免按坏长度越界读镜像。

## B 次：把不变量变成检查规则

至少实现：

- inode 引用块越界。
- inode 引用保留块或日志块。
- 两个不允许共享的 inode 引用同一数据块。
- inode 引用块但块位图标为空闲。
- 块位图标占用但没有系统保留用途、inode 或目录结构引用。
- 目录项指向未分配 inode。
- inode 位图标空闲但被目录项引用。
- 普通文件 `size` 需要的逻辑块缺少直接块指针。
- 根 inode 不存在或不是目录。

对于“位图占用但无人引用”，要排除超级块、位图、inode 表、日志区、根目录初始块等固定保留区域，不能把合法系统块误报成泄漏。

## 构造可重复坏镜像

不要只依赖第 44 课一次崩溃的偶然结果。增加一个宿主机测试工具或脚本，对基线镜像副本做受控字节修改，分别制造：

```text
1. 清掉一个仍被 inode 引用的数据块位图位
2. 把两个 inode 的直接块指针改成同一块
3. 把目录项 inode 号改成未分配项
4. 把文件大小改到需要一个不存在的直接块
```

每个坏镜像只制造一种主要错误，便于验证检查器确实定位了目标问题。

## 输出要求

错误不要只打印 `filesystem corrupted`，至少包含：

```text
error kind
inode number / directory entry
block number
expected relation
actual relation
```

示例形状：

```text
BLOCK_BITMAP_MISMATCH: inode=7 direct[0] -> block=25, bitmap says free
DUPLICATE_BLOCK: block=31 referenced by inode=4 direct[1] and inode=9 direct[0]
```

## 验收

- [ ] 第七阶段正常镜像扫描后零错误。
- [ ] 四类人工坏镜像分别出现预期错误且位置正确。
- [ ] 第 44 课崩溃镜像能由检查器解释，而不是只表现为“挂载失败”。
- [ ] 检查器不修改输入镜像；运行前后文件校验值相同。
- [ ] 坏超级块不会诱导工具按错误边界越界读取。
