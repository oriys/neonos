# 第 27 课：用管道连接两个进程

状态：待开始。前置：[第 26 课](26-fork.md)。分 A、B、C 三次，每次 45～60 分钟。

## 目标与导读

实现有限容量字节管道、fd 引用与等待。可对照 [MIT xv6 的管道实现](https://github.com/mit-pdos/xv6-riscv/blob/riscv/kernel/pipe.c) 理解缓冲区、读写端关闭与唤醒；本课程沿用自己的重试式调用模型，不直接移植其睡眠调用栈。

## A 次：先认识 fd 与端点

1. 每进程固定 8 个 fd；0、1、2 初始指向控制台输入、输出、错误输出。fd 是进程内索引，不是物理地址。
2. 全局固定管道池，例如 4 个对象，每个有 512 字节环形缓冲、读写位置、长度、读端和写端引用数。
3. `pipe(pair_ptr)` 先验证可写的 8 字节结果区，再原子地分配对象和两个 fd，失败完整回滚。
4. fork 复制条目并增加相应引用；exec 保留条目；close 和 exit 减引用并触发必要唤醒，读写端引用都归零才释放对象。
5. 实现 dup2：先验证 src 与 dst；二者相同直接返回；否则正确替换 dst 原条目并更新引用，不能误关闭 src 的最后引用。

约 15 分钟图解、25 分钟实现、15 分钟引用计数核对。

## B 次：传输与阻塞

1. read 先验证可写用户范围，write 先验证可读范围；最大请求按阶段约定。通过固定内核缓冲区复制，暂不支持异步 DMA 或保留用户引用。
2. 非空管道读出至多请求长度并返回实际数；有空间则写入可容纳部分并返回实际数。用户循环处理部分完成。
3. 空但仍有写者时，读调用无副作用地登记 Blocked；满但仍有读者时，写调用同理。重试模式使用第 25 课约定，唤醒后重新校验。
4. 条件检查、等待登记和缓冲区修改处于单核不可抢占区间；写入后唤醒读者，读出后唤醒写者。
5. 已经传输非零字节就返回数量，不登记重试并重复传输。读取前确认 copyout 可以完成，失败不消费缓冲区字节。
6. 使用总长超过 512 字节的已知模式，从多次 write 传到多次 read，检查总长度与校验值。

## C 次：关闭也会改变等待条件

1. 缓冲区为空且所有写端引用关闭，read 返回 0 表示 EOF；仍有残留数据时先返回数据，读尽后才 EOF。
2. 所有读端关闭，write 返回 -8，并唤醒此前因满而等待的写者。本课不实现 SIGPIPE。
3. 父子所有继承或 dup2 产生的端点都参与计数；关闭一个 fd 不一定等于关闭最后写端。
4. 测试错误 fd、错误方向、跨页无效缓冲区、对象池耗尽、半满部分写和最后一端关闭。
5. 故意保留一个多余写端，观察读者等待，再修正关闭路径；失败实验有超时和等待原因报告。

## 常见问题与验收

| 现象 | 先检查 |
| --- | --- |
| 输出完却收不到 EOF | 父或另一个子进程是否还持有写端 |
| 内容重复 | 部分成功后是否错误重试原请求 |
| 指针错误导致数据丢失 | 是否在验证 copyout 前推进读位置 |
| 最后一端关闭后对象仍占用 | fork、dup2、exit 的引用是否成对处理 |

- [ ] 数据完整，部分读写正确，空满可唤醒。
- [ ] EOF、无读者错误及引用继承语义正确。
- [ ] 非法参数和资源不足不改变已有管道状态。
- [ ] 新检查覆盖计数和超时，更新 [进度记录](progress.md)。
