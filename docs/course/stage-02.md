# 第二阶段：运行第一个用户程序

状态：课程已安排，学习待开始。入口：[总路线](README.md) · [进度记录](progress.md)。

目标：让一个内嵌程序在用户态运行，通过系统调用打印字符和退出；内核能区分用户程序错误与自身故障，并在程序结束后继续执行管理流程。

阅读对应 [OSTEP 官方章节](https://pages.cs.wisc.edu/~remzi/OSTEP/) 第 4 章 Processes、第 5 章 Process API、第 6 章 Direct Execution。章节给出概念，本目录给出 neonos 的配套实现练习。

## 实现边界

本阶段只有一个正在运行的用户程序，保持单核、固定容量、不使用堆分配、不启动调度定时器。多个程序按顺序运行，不交替运行。用户程序先用短小的整数汇编编写并链接进内核镜像，避免同时引入独立工具链、ELF 加载器和用户 Rust 运行时。

内核为受控程序准备独立用户栈，但尚未建立页表和进程地址隔离。U 模式能限制特权指令，不能据此声称已阻止程序读写所有内核内存或直接访问设备；实际物理访问还受固件的 PMP 配置影响。阶段验收使用已知程序，不用恶意内存写入实验证明安全性。

不依赖“用户打印了 U”来证明模式切换：进入异常处理后检查保存的来源信息和异常类型。若用户程序陷入无限循环，此阶段尚不能抢占，退出 QEMU 后排查；定时抢占是第三阶段目标。

## 共同约定

以下是课程自定义协议，不是 Linux 系统调用号或 SBI 协议。后续课程沿用，避免每课重新定义。

| 请求 | `a7` | 参数 | 返回 |
| --- | --- | --- | --- |
| `putchar` | 1 | `a0` 为 0～127 的 ASCII 值 | 成功为 0；越界为 -2 |
| `exit` | 2 | `a0` 为 0～255 的退出码 | 有效请求不返回；越界返回 -2 |
| 未知请求 | 其他 | 忽略 | 返回 -1 |

返回值按 RV64 有符号整数解释。`ecall` 发起请求，内核把结果写入保存现场中的 `a0`。本阶段无字符串指针参数；缓冲区访问验证安排在内存隔离课程。

计划产物：`src/process.rs` 保存单个进程记录；`src/user.S` 保存受控程序；`src/syscall.rs` 分发请求；扩展第一阶段的 `src/trap.rs`、`src/trap.S`；第 10 课整理 `src/user_api.S`；阶段末新增 `tests/user.sh`。这些文件在上课实现时逐步创建。

## 总验收场景

| 场景 | 预期 |
| --- | --- |
| 两次字符请求 | 输出 `OK`，用户执行完两个调用后的检查 |
| 未知请求 | 用户收到 -1，仍可继续请求输出 |
| 非法字符参数 | 用户收到 -2，不输出被截断的字符 |
| 有效退出码 7 | 记录 `Exited(7)`，内核管理流程继续 |
| 非法退出参数 | 用户收到 -2，程序没有提前退出 |
| 用户非法指令 | 记录 `Faulted` 和诊断信息，随后能启动正常程序 |
| 内核受控故障，单独运行 | 保留诊断并停止，不伪装成用户退出 |
| 正常程序重复运行 100 次 | 次数准确，每次重新初始化，最后出现阶段完成标记 |

既有 `./tests/boot.sh` 只证明 Hello 启动路径。新阶段检查要捕获完整实验结果，验证关键标记的顺序、次数、超时和意外 panic；不能只看到第一行就成功。
