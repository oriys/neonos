# 第 04 课：给内核画一张内存地图

状态：待开始。前置：[第 03 课](03-panic.md) 验收完成。拆成 A、B 两次，每次 45～60 分钟。

## 目标与预习

输出内核各区域的边界，解释启动栈的用途，并让启动代码明确初始化普通 BSS。

回看 OSTEP 第 2 章的内存管理动机。本课观察当前内核实际布局；地址空间和分页将在后续阶段学习。Rust 外部符号写法参考 [External blocks](https://doc.rust-lang.org/reference/items/external-blocks.html)：本项目采用 2024 edition，需要 `unsafe extern "C"`。

## A 次：先看地图，不改初始化流程

时间：图解 15 分钟、符号与打印 25 分钟、验证复盘 10 分钟。

打开 [linker.ld](../../linker.ld)，按顺序找到各输出段。再回到 [src/main.rs](../../src/main.rs) 找启动栈的汇编声明。

| 区域 | 先这样理解 | 当前例子 |
| --- | --- | --- |
| `.text` | 要执行的机器指令 | `_start` 和 Rust 函数 |
| `.rodata` | 只读内容 | 问候语等常量数据，具体归属以构建结果为准 |
| `.data` | 有非零初值的可写静态数据 | 本课可添加一个实验变量 |
| 普通 `.bss` | 需要零初值的可写静态数据 | 本课的清零探针 |
| 启动栈 | 函数临时工作空间 | 汇编预留的 64 KiB |

1. 给各段添加开始与结束符号，例如 `stext/etext`、`srodata/erodata`、`sdata/edata`。
2. 把 `.bss.stack` 首先收集到独立输出段 `.boot_stack (NOLOAD)`，仍保留原栈标签，并提供 `sboot_stack/eboot_stack` 边界。
3. 后面再收集普通 `.bss`，用 `sbss/ebss` 包围普通 BSS 内容。确保 `.bss.*` 的匹配不会把启动栈再次并入待清零范围。
4. 创建计划中的 `src/memory.rs`，声明链接符号；取得符号的地址，用第二课的工具按十六进制打印。
5. 核对每个区间的开始不大于结束、各区域不重叠；启动栈大小仍为 65536 字节。

链接符号是地址标记，获取边界时不要解引用为“变量内容”。打印地址的辅助函数与启动清零职责分开。链接脚本有改动时可运行 `touch src/main.rs` 触发重新链接，避免观察到旧构建产物。

## B 次：明确谁把 BSS 清零

时间：清零范围 10 分钟、启动修改 20 分钟、对照实验 20 分钟、复盘 10 分钟。

本课选择在 `_start` 中、调用 Rust 之前用汇编清零普通 BSS。这样初始化发生在 Rust 使用任何静态数据之前。先保留设置 `sp` 的步骤，只清理 `[sbss, ebss)`；栈已经放在独立区域。

算法示意，不是可粘贴的汇编实现：

```text
准备 sp
cursor = sbss
end = ebss
while cursor < end:
    写入一个零字节
    cursor += 1
call rust_main
```

1. 用 `la` 取得边界，用临时寄存器保存游标和结束地址。
2. 每轮先判断是否到达结束边界，再用 `sb` 写一个字节并前进。
3. 空区间必须直接跳过；结束地址不属于清零区域。
4. 不调用 Rust 打印来调试这段初始化；初始化完成后再打印边界和结果。

### 证明清零代码真的执行了

仅仅观察变量等于零不够，因为加载器可能已经提供零内存。

在普通 BSS 中专门预留并导出一个 8 字节探针。测试时在汇编清零循环前把它填成非零，循环后进入 Rust，以原始指针读取探针并输出。不要创建长期存活的可变静态引用。

- 开启清零：探针结果应为零。
- 临时跳过清零：探针应保留刚写入的非零值；这次对照应在当前尚无其他依赖 BSS 初值的运行状态时进行。
- 恢复清零并移除填充步骤，保留边界检查和正常启动验证。

当前只有一个 hart；多核同时清零和访问内存不在这个练习范围内。

## 常见问题

| 现象 | 先检查 |
| --- | --- |
| 新布局后无法启动 | `_start` 是否仍在入口，启动栈标签是否仍有效 |
| 清零后崩溃 | 范围是否覆盖栈或代码、循环是否写过 `ebss` |
| 打印出来像普通小整数 | 是否误读了边界处的内容而没有取地址 |
| 探针总是零 | 汇编是否确实填入非零、读取是否被优化成常量、是否运行了新构建 |
| 修改链接脚本没变化 | 是否触发了重新链接 |
