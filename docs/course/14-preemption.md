# 第 14 课：程序不让出，内核也能切换

状态：待开始。前置：[第 13 课](13-timer.md) 验收完成。分 A、B 两次，每次 45～60 分钟。

## 目标与导读

把第 12 课的就绪队列与第 13 课的定时事件连接起来，实现抢占式 RR。复习 OSTEP 第 6～7 章，区分“保存和恢复现场的机制”与“选择下一任务的策略”。

先打开已实现的任务切换动作、定时处理和退出路径。它们应汇合到中央调度循环，避免每个事件都复制一份切换代码。

## A 次：接入时间片

时间：规则 10 分钟、接入 25 分钟、双任务验证 20 分钟。

1. 先设每个时间片为一个定时周期。记录 `dispatch`、`yield`、`timer`、`exit`、`fault` 等原因，明确当前编号。
2. 用户定时事件到来：先处理预约与记录，再保存当前现场，把仍可运行的任务放回队尾，回到调度循环选下一项。
3. 明确每次派发前的期限：本课为新派发任务预约 `now + quantum`，避免复用前一任务已临近的期限。
4. 当只有一个 Ready 任务时可再次选中它；不能因为切换目标与原任务相同就漏恢复现场。
5. 准备两个不调用 `yield` 的长整数计算任务，每个只在完成时通过用户接口报告校验结果并退出。
6. 调整工作量使两者在完成前都经历定时事件。检查日志中存在由 `timer` 引起的 A→B、B→A，且最终结果正确。

仅看到串口字符交错不足以证明抢占；必须确认计算段内没有让出调用，且发生过定时原因的切换。

## B 次：处理调度边界

时间：临界区 15 分钟、边界场景 25 分钟、检查复盘 20 分钟。

1. 内核更新队列、打印和切换现场时保持 S 模式中断关闭，不在处理器中主动开放嵌套中断；用户入口安装、可信栈信息与当前编号应在返回前全部就绪。
2. 内核临界区可能延迟定时事件，返回用户后再处理。测量并记录长处理路径，不承诺精确硬实时响应。
3. 退出与用户故障不重新入队，其余任务继续；终态资源回收到调度栈上进行。
4. 全部结束时关闭计时，输出各任务的完成和失败状态；本阶段无等待任务，不需要实现可能等待未来唤醒的空闲循环。
5. 分别验证单任务、多任务、提前退出、用户故障和全部结束。人为在内核中触发故障的场景仍单独报告并停住。
6. 计划创建 `tests/scheduling.sh`：验证定时切换原因、完成次数、计算校验和最终标记，拒绝意外 panic，设置超时并清理 QEMU。

新增计时不会允许用户读取内核数据；它也没有补齐地址隔离。测试只用已知程序，不把此课结论扩大为安全运行任意程序。

## 常见问题

| 现象 | 先检查 |
| --- | --- |
| 计时发生，但总是 A | 当前任务是否放回队尾，是否每次都从固定槽取任务 |
| 程序越切越慢或栈耗尽 | 是否积累旧陷入帧或嵌套进入调度函数 |
| 出错任务一直被调度 | Faulted 是否被误当作 Ready |
| 打印时偶尔挂住 | 是否在内核开放了中断，进入尚不支持重入的输出路径 |

## 验收

- [ ] 两个不主动让出的程序都被定时抢占并完成校验。
- [ ] 退出或用户故障只结束对应任务，其他任务继续。
- [ ] 队列无重复，最多一个 Running，终态不再运行。
- [ ] 计时关闭后完成路径稳定，既有检查与新检查通过。
- [ ] 更新 [进度记录](progress.md)，说明观察到的切换原因。
