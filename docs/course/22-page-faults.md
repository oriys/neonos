# 第 22 课：错误地址，也要有清楚的处理方式

状态：待开始。前置：[第 21 课](21-address-spaces.md)。分 A、B 两次，每次 45～60 分钟。

## 目标与阅读

区分未映射、权限错误与内核故障，验证系统调用传来的地址。阅读 OSTEP 第 15、18、21 章。本课先诊断并终止非法用户访问，不实现按需分配或从磁盘调页。

## A 次：有意触发可解释的页故障

1. 按来源与原因分类，记录进程编号、根表、`sepc`、`stval` 和软件页表查询结果。取指、读、写页故障的编号按 RISC-V 规范核对，不混同物理访问故障。
2. 使用受控用户汇编分别访问未映射页、写只读代码页、从不可执行数据页取指、读取内核 U=0 页和触及栈保护页。
3. 每次用新实例，预期当前进程 Faulted，然后正常程序可运行；记录真实地址，不硬编码所有故障的 `stval` 都非零。
4. 内核自身故障仍报告停住，单独实验。不要给所有缺页一律补映射，否则会取消既定权限和保护页。

约 15 分钟分类、25 分钟分场景触发、15 分钟复盘。用户故障样例由汇编构造，避免用 Rust 未定义行为做实验。

## B 次：验证跨页用户缓冲区

新增自定义调用 `write_buf`：`a7=4`，`a0=用户地址`，`a1=长度`；最多 256 字节，成功返回字节数，长度过大返回 -2，无效用户地址返回 -3，长度为零返回 0 且不访问地址。原调用与错误码保持兼容。

1. 在计划中的 `user_copy.rs` 先检查长度与 `start + len` 的整数溢出，再按页遍历整个范围。
2. 每页必须映射到本进程合法用户 RAM，并具有 U 与读取权限；不能只检查起始地址，不允许用内核映射或 MMIO 冒充缓冲区。
3. 第一版不临时打开 SUM 直接解引用用户虚拟地址，而是查表后通过可信的内核 RAM 映射读取对应物理页片段，复制到固定 256 字节内核缓冲区。
4. 复制过程保持当前映射稳定：单核、内核不抢占、不支持同时修改该地址空间；不跨调度保留用户指针或页引用。未来加入共享映射和多核后要重新审视此前提。
5. 完整验证并复制后才输出，保证第二页无效时不先输出第一页；原始输出缓冲区保存的是字节，不需要假定 UTF-8。
6. 用用户分支验证返回值，测试跨两页有效、第二页未映射、内核指针、地址回绕、超过长度限制和零长度。

## 常见问题与验收

| 现象 | 先检查 |
| --- | --- |
| 第一页能读，跨页就崩 | 是否逐页检查并按页边界复制 |
| 传内核地址竟然成功 | 是否检查 U 权限与合法用户物理页归属 |
| 非法第二页也输出了部分内容 | 是否先完整复制后输出 |
| 所有错误都变成用户终止 | 系统调用参数错误应返回 -3，直接非法访存才结束任务 |
