# 第 42 课：给文件取名字

状态：待开始。前置：[第 41 课](41-inodes.md)。分 A、B 两次，每次 45～60 分钟。

## 目标与阅读

阅读 OSTEP 第 39～41 章，理解名称到 inode 的映射。目录也是由 inode 与数据块保存的结构，但只能通过目录接口修改，不能当普通文件任意写入。

## A 次：逐级查找

1. 从根 inode 1 开始解析绝对路径，总长度最多 128 字节，单段名称 1～56 字节。
2. 第一版使用可打印 ASCII 名称，拒绝 NUL、空段、重复斜杠、`.` 和 `..`；路径 `/` 单独表示根。末尾斜杠先拒绝，避免规则含混。
3. 每到下一段前检查当前 inode 是目录；校验目录项长度、类型及被引用 inode 的有效性。
4. 文件不存在和中间分量不是目录分别报错，不能一律当作需要创建。

## B 次：创建与列举

1. 创建文件或 mkdir 时先查父目录与重名，预留 inode、目录扩展所需块以及新目录块，再发布目录项。
2. 单核同步文件系统路径保持串行，重复名称创建只能有一个成功；不持有用户同步锁来保护内部元数据。
3. 失败释放本次预留，既有目录项不变。磁盘写入错误按阶段错误模式处理，正常回滚不等于崩溃原子性。
4. 列举只返回有效目录项；保留固定容量和最大目录大小限制，满时明确失败。
5. 创建 `/notes` 和 `/notes/first`，sync 后重启列举并读取文件，验证名字指向同一内容。

## 常见问题与验收

| 现象 | 先检查 |
| --- | --- |
| 找到名字却访问越界 | 是否校验 inode 号和分配位 |
| 重名产生两个目录项 | 查重和发布是否处于同一串行操作 |
| 一次失败后 inode 数减少 | 预留 inode 是否完整回滚 |

- [ ] 多层路径、根、重名、名称边界与类型错误可验证。
- [ ] 创建和列举重启后正确，格式错误不越界访问。
