# 第 24 课：进程不变，换一个程序运行

状态：待开始。前置：[第四阶段](stage-04.md)。分 A、B 两次，每次 45～60 分钟。

## 目标与阅读

回看 [OSTEP 第 5 章](https://pages.cs.wisc.edu/~remzi/OSTEP/) 的程序替换概念。把第四阶段的固定用户样例封装为可选择加载的内嵌程序集合，先不实现磁盘路径和通用 ELF 解析。

## A 次：构建待运行映像

1. 在计划中的 `program.rs` 建立固定 ID→名称、镜像范围、入口偏移、用户段布局的目录；资源来自内核已链接内容，不接受用户随意指定内核指针。
2. 提取 `build_image`：验证入口属于可执行段、各段和栈不重叠、长度计算无溢出，使用第四阶段接口构造新根与私有页。
3. 复制镜像并初始化零数据、栈和用户整数现场，执行必要的指令同步。样例继续遵守第四阶段的用户代码可重定位约定。
4. 让构造返回完整候选映像或错误。遇到内存不足，释放所有本次分配，不改当前进程。

约 15 分钟目录设计、25 分钟提取、15 分钟验证。先直接由测试管理器调用构造，核对页表和页数。

## B 次：提交替换

1. 添加阶段协议的 `exec(program_id)`。先构建候选，再在安全点提交，保留 PID 和父子关系。
2. 新用户现场从入口开始，不继承旧程序寄存器和栈数据；成功不返回旧 `ecall` 后的代码。
3. 先切到可继续执行的可信根与调度栈，确保不再使用旧用户根，再回收旧映像。不要释放进程仍需使用的陷入栈或进程记录。
4. 未知 ID 返回 -6；资源不足返回 -4。失败应能在旧程序打印 `exec failed; still running`。
5. 第 27 课加入 fd 后，exec 默认保留已打开描述符，供管道重定向使用；本阶段不实现 close-on-exec 标志。

## 常见问题与验收

| 现象 | 先检查 |
| --- | --- |
| 成功后仍打印旧程序标记 | 是否恢复了旧现场或旧返回地址 |
| 失败后旧程序损坏 | 是否在候选完整之前释放旧映像 |
| 每次替换都少几页 | 失败回滚与旧根回收是否完整 |

- [ ] A 程序替换成 B，PID 相同，旧成功后路径不可达。
- [ ] 未知程序和分配失败保留原映像。
- [ ] 重复替换后页数稳定，更新 [进度记录](progress.md)。
