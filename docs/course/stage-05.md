# 第五阶段：从进程接口到小 shell

状态：课程已安排，学习待开始。入口：[总路线](README.md) · [进度记录](progress.md)。

目标：替换正在运行的程序，创建和等待子进程，通过管道传输数据，最终在用户态 shell 输入命令并运行 `hello | cat`。

阅读 [OSTEP 第 5 章 Process API](https://pages.cs.wisc.edu/~remzi/OSTEP/)，结合前面的调度与地址空间课程。下面是 neonos 教学协议，不承诺 POSIX 或 Linux 二进制兼容。程序来自内嵌集合，磁盘文件系统仍在第七阶段实现。

## 对前几阶段的扩展

此前任务结束后立即释放记录；现在用户页可在安全点释放，但保留最小 Zombie 记录供父进程等待。此前队列空代表全部结束；现在可能只是所有任务 Blocked，需要检查等待原因与外部事件。

沿用中央调度循环，不在任意 Rust 内核调用栈中睡眠。不能完成的调用在无副作用的条件下登记等待、保存原参数及原 `ecall` 地址，然后回调度栈；唤醒后重试同一条 `ecall`。完成或返回错误才前移地址。已经传输部分数据则返回实际数量，不倒回重试并重复产生副作用。

条件检查与登记 Blocked 在同一个单核不可抢占区间完成；唤醒只做一次 Blocked→Ready。MLFQ 的已用 CPU 配额跨阻塞保留，等待不记 CPU 时间，周期提升覆盖等待任务但不把它们提前入队。内核不支持多线程同时修改同一地址空间，重试仍须重新验证指针和 fd。

## 新接口约定

保留已有调用号 1～4，新增如下。参数依次用 `a0`、`a1`、`a2`，返回值用有符号 `a0`。

| 调用号 | 名称与参数 | 成功结果 |
| --- | --- | --- |
| 5 | `exec(program_id)` | 替换当前映像，不回旧调用点 |
| 6 | `wait(child_pid, status_ptr)` | 返回被回收子 PID，写入 32 位状态 |
| 7 | `fork()` | 父得到子 PID，子得到 0 |
| 8 | `pipe(pair_ptr)` | 返回 0，写入两个 32 位 fd：读端、写端 |
| 9 | `read(fd, buf, len)` | 返回实际字节数；管道 EOF 为 0 |
| 10 | `write(fd, buf, len)` | 返回实际字节数 |
| 11 | `close(fd)` | 返回 0 |
| 12 | `dup2(src, dst)` | 返回目标 fd |

错误码：-1 未知调用；-2 非法参数或长度；-3 用户地址无效；-4 资源不足；-5 无此子进程；-6 无此程序；-7 无效 fd 或端点方向；-8 管道已无读者。它们是课程定义，禁止与宿主机 errno 混用。

每次读写最多 256 字节，先校验 fd、方向与长度，零长度返回 0 且不访问缓冲区。`wait` 状态约定：正常退出为 0～255，用户故障为 `0x10000 | cause`。只等待指定直接子进程，不支持通配等待和信号。PID 带代际或单调不复用标识，避免旧 PID 命中新实例。

## 计划产物与范围

计划新增 `src/program.rs`、`src/fd.rs`、`src/pipe.rs`、等待状态与用户复制写回接口，扩展调度、进程和用户调用封装；内嵌用户样例中加入 shell、hello、cat；新增 `tests/process.sh`、`tests/shell.sh`。

先使用有限整数汇编和固定缓冲区实现样例 shell。若需要迁移成 Rust 用户程序，单独增加用户运行时、构建和链接补课，不能假设内核里的普通 Rust 函数可直接作为用户 shell。

## 总验收

- [ ] exec 成功换映像且 PID 不变，失败时旧程序仍能运行。
- [ ] wait 覆盖先退出、后退出、重复等待和无效指针。
- [ ] fork 返回值正确，父子用户数据与栈隔离，失败不遗留半成品。
- [ ] 管道支持部分读写、空满阻塞、EOF 和无读者错误。
- [ ] fork/dup2/close/exit 的端点引用数一致，继承的多余写端会被关闭。
- [ ] 用户态 shell 可运行内嵌命令，未知命令和超长输入有可读反馈。
- [ ] `hello | cat` 完成，两子进程都被回收，再次显示提示符。
- [ ] 重复命令与管道后页数、进程槽与管道对象计数恢复到基线。

完成后进入 [第六阶段并发](stage-06.md)，进一步理解线程、锁与同步。
