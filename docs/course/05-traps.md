# 第 05 课：捕获第一次 CPU 异常

状态：待开始。前置：[第 04 课](04-memory-layout.md) 验收完成。拆成 A、B 两次，每次 45～60 分钟；汇编保存现场可额外拆练。

## 本课终点

在内核中受控触发异常，保存整数寄存器现场，打印原因与指令地址，然后等待。第一阶段的处理器是不会返回的诊断入口；恢复执行、用户态切换和定时器将在后续课程实现。

预习 OSTEP 第 6 章 Direct Execution 的控制权问题；寄存器含义按 [RISC-V Supervisor 规范](https://docs.riscv.org/reference/isa/priv/supervisor.html) 查询 `stvec`、`sepc`、`scause`、`stval`。只查本课用到的内容即可。

## A 次：先接好入口

时间：概念 15 分钟、现场布局 15 分钟、入口和安装 20 分钟、验证 10 分钟。

### 认识 4 个记录本

CSR 可以先理解为 CPU 提供的一组控制和状态寄存器。

| 名字 | 本课用途 |
| --- | --- |
| `stvec` | 指定交给 S 模式处理的异常从哪里进入 |
| `sepc` | 记录相关指令地址 |
| `scause` | 区分中断或异常，并记录原因编号 |
| `stval` | 保存异常相关辅助信息；某些情况可以为零 |

使用 Direct 模式，入口至少 4 字节对齐。本课保持普通中断关闭。同步异常的处理与主动开启定时中断不是一回事。[RISC-V Supervisor 规范](https://docs.riscv.org/reference/isa/priv/supervisor.html)

### 分步接入

1. 计划创建 `src/trap.S` 存放汇编入口，用 `global_asm!(include_str!("trap.S"))` 接入；创建 `src/trap.rs` 存放初始化和 Rust 报告函数。
2. 在 Rust 中定义 `#[repr(C)]` 的 `TrapFrame`，使用 32 个 `usize` 槽位记录整数寄存器，再记录 `sstatus`、`sepc`、`scause`、`stval`。明确每个字段在 RV64 下的字节偏移，逐项列成表。
3. 入口在现有可用的内核栈上预留 288 字节：36 个 8 字节槽位，保持调用 Rust 时的 16 字节栈对齐。此设计仅用于当前内核态受控实验，不处理坏栈或嵌套异常。
4. 先保存原始通用寄存器，再借临时寄存器读取 CSR。`x0` 槽记录零；`x2` 槽要记录分配现场之前的 `sp`。必须先保存用来计算原始 `sp` 的临时寄存器，再覆盖它。
5. 把现场地址放入第一个参数寄存器 `a0`，调用具有 `extern "C"` ABI 和固定符号名的 Rust 报告函数，返回类型为 `!`。汇编在调用后仍留等待兜底路径。
6. 初始化函数将入口地址写入 `stvec`。从 `rust_main` 调用初始化，再打印 `trap ready`。

这些是实现时逐条完成的任务，不要把只有 Rust 函数地址、没有汇编入口的函数直接当作完整异常处理器。CPU 不会替你完成普通函数调用所需的全部现场保存。

A 次验收：构建成功，`Hello kernel` 和 `trap ready` 都出现；原启动检查通过。此时没有主动制造异常。

## B 次：制造一次能解释的错误

时间：触发准备 10 分钟、报告 20 分钟、对照检查 15 分钟、复盘 10 分钟。

1. 报告函数先打印 `[trap]`，再以十六进制输出 `scause`、`sepc`、`stval`，最后进入等待。
2. 在独立汇编函数中添加显式的非法指令编码 `.4byte 0`，为触发点定义可导出的标签。初始化异常入口后再调用该函数。
3. 触发前打印该标签地址，异常后将它与 `sepc` 对照。触发点来自汇编，避免用 Rust 空指针解引用制造未定义行为。
4. 观察到非法指令异常时，核对 `scause` 的中断标记未设置、原因编号为 2。辅助字段记录实际值，不要求它非零。
5. 当前 OpenSBI 的异常委派配置决定该异常是否交给 S 模式；如果固件接管而内核没有报告，先检查固件输出和委派情况，不把所有无输出现象归因于打印错误。
6. 移除主动触发调用，保留入口初始化和报告功能，再验证普通启动。

预期报告形状：

```text
Hello kernel
trap ready
trigger at 0x...
[trap]
scause=0x2 sepc=0x... stval=0x...
```

不要通过随意增加 `sepc` 后执行 `sret` 来“修好”异常；本课没有恢复执行路径，且目标支持不同长度的指令。现场保存也只覆盖本课使用的整数状态，不宣称已支持浮点任务或任意上下文恢复。

## 常见问题

| 现象 | 先检查 |
| --- | --- |
| 连 `trap ready` 都没有 | 是否成功构建、初始化之前是否已出错 |
| 触发后静默 | `stvec` 地址和对齐、固件委派、入口汇编是否链接进来 |
| `[trap]` 无限重复 | 处理器是否再次异常、栈偏移是否错误、打印是否递归 |
| 地址与触发点不一致 | 是否保存 CSR 太晚，或打印/入口本身先发生异常 |
| Rust 中字段全是怪值 | 汇编偏移与 `#[repr(C)]` 布局是否一致，是否传了现场地址 |

## 验收与阶段复盘

- [ ] 受控实验报告非法指令原因，`sepc` 与触发点一致。
- [ ] 报告后稳定等待，无递归报错；移除触发调用后正常启动。
- [ ] 原启动检查通过，另外记录本课报告，完成 [阶段总验收](stage-01.md)。
