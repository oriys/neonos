# 第 25 课：孩子结束了，父进程怎样知道

状态：待开始。前置：[第 24 课](24-exec.md)。分 A、B 两次，每次 45～60 分钟。

## 目标与前置补充

实现指定子 PID 的 wait。此时 fork 尚未完成，先由内核测试管理器创建带父子关系的两个实例；第 26 课再用真正 fork 替换夹具。

用户复制此前只有读入；本课补充 `copy_to_user`，逐页验证 U 与写权限、范围和溢出。wait 的状态写入成功前不能回收子记录。

## A 次：先保留退出结果

1. 进程记录增加父 PID、子关系和 Zombie 状态。用户退出或故障后在安全点释放大块用户资源，保留 PID、父关系和结束状态。
2. 父调用 wait 时只查直接子进程。若已经 Zombie，验证 4 字节状态缓冲区、写回状态，然后回收最小记录并返回子 PID。
3. 没有此子进程返回 -5；状态指针无效返回 -3，子进程仍可被之后的合法 wait 回收。
4. 同一子进程只能成功回收一次。PID 标识不可仅等于可复用槽号。

约 15 分钟状态图、25 分钟实现、15 分钟实验。先让子进程退出，再执行父 wait，验证“先退出后等待”。

## B 次：子进程还活着就等待

1. 在单核不可抢占区间检查子状态并登记 `Blocked(WaitChild(pid))`，避免两步间漏掉退出事件。
2. 没有副作用时保留原调用参数与 `ecall` 地址，处理函数返回调度动作，不在 Rust 函数中永久等候。
3. 子结束时唤醒对应父进程，Blocked→Ready 只做一次；父再次运行重试调用，重新检查状态和指针。
4. 父先结束时，把存活孩子交给内核管理者；管理者自动回收其未来结束记录，已退出孤儿也及时回收。不需要为了本课实现完整 init 进程。
5. 就绪队列空但仍有 Blocked 不算实验完成。没有任何可唤醒来源时报告测试停滞，保留诊断；有外部输入的空闲等待在第 28 课接入。

## 常见问题与验收

| 现象 | 先检查 |
| --- | --- |
| 父永远不醒 | 条件检查和登记是否原子化，退出是否查对应等待者 |
| 无效指针后再 wait 找不到孩子 | 是否过早回收 Zombie |
| 父退出后槽位耗尽 | 孤儿是否有人负责回收 |

- [ ] 两种先后时序、重复 wait 和非子 PID 都有正确结果。
- [ ] 无效输出指针不吞掉结束状态。
- [ ] Blocked 不在 Ready 队列中，唤醒后不重复入队。
- [ ] 正常退出与用户故障均可回收，更新 [进度记录](progress.md)。
