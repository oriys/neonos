# 第 19 课：手工搭建一棵页表

状态：待开始。前置：[第 18 课](18-heap.md)。分 A、B 两次，每次 45～60 分钟。

## 目标与阅读

阅读 OSTEP 第 18、20 章；查 [RISC-V Supervisor 规范的 Sv39](https://riscv.github.io/riscv-unified-db/manual/html/isa/isa_20240411/chapters/supervisor.html)。本课构造页表并用软件查询，暂不写 `satp`。

## A 次：从地址走到表项

1. 学习 Sv39 的三级索引与 12 位页内偏移：每级 9 位，每张表 512 个 8 字节表项，占一页。
2. 在计划中的 `page_table.rs` 区分表项中的物理页号与软件访问表页用的地址，不把物理页号直接当指针。
3. 整理有效位、读写执行、用户权限和访问/脏位；非叶项指向下一级，叶项指向被映射页。本课只允许最底层 4 KiB 叶项。
4. 页表页从第 17 课分配并清零。先手填一条映射，再打印三级索引和最终物理地址。
5. 检查地址满足 Sv39 的规范形式；映射入口拒绝未对齐页地址、非法权限组合及不支持的大页。

前 20 分钟图解、25 分钟构造、10 分钟核对。本课策略预先设置叶项 A 位，可写页设置 D 位，避免把访问/脏位维护混入首次分页实验。

## B 次：建立三个操作

1. `map_page`：缺少中间表才分配，重复映射默认拒绝，不能悄悄覆盖。
2. `translate`：逐级检查有效性和叶项，返回物理地址与权限；查询本身不创建表页。
3. `unmap_page`：撤销映射并返回原映射信息，不自动释放用户数据页。表页和数据页的回收责任分别记录。
4. 中途分配失败时回滚本次新建表页和修改，保留原有映射。
5. 用小页池强制构建中途耗尽，核对已有映射仍正确、空闲页数恢复。

## 常见问题与验收

| 现象 | 先检查 |
| --- | --- |
| 不同虚拟页查到同一表项 | 索引移位或掩码是否错位 |
| 空查询使空闲页减少 | 查询是否误用了创建路径 |
| 映射失败后页数变少 | 新建中间表是否回滚 |

- [ ] 手算与软件查询地址一致，跨页边界无混淆。
- [ ] 权限、重复映射、撤销和失败回滚通过。
- [ ] 能解释三级表与叶项，不要求背全部位号。
- [ ] 更新 [进度记录](progress.md)。

小练习：解释为什么一页用户数据可能需要额外的页表页。
