# 第 26 课：一次调用，父子两条执行路线

状态：待开始。前置：[第 25 课](25-wait.md)。分 A、B 两次，每次 45～60 分钟。

## 目标与阅读

阅读 OSTEP 第 5 章 fork 的行为。实现立即复制用户内存的简化版本，不使用写时复制。父得到子 PID，子得到 0，二者都从 fork 调用之后继续。

## A 次：复制哪些，重建哪些

1. 预留空进程槽，但不先入队。分配独立用户根、用户页和陷入栈，重建共同的内核映射。
2. 逐页复制父拥有的用户代码、数据和栈，保留虚拟地址和权限；未映射保护页保持未映射，不复制内核物理页作为用户页。
3. 复制用户整数现场。父子返回地址都越过同一 `ecall`，父 `a0=child_pid`，子 `a0=0`；子内核调度上下文重新建立，不复制指向父陷入栈的引用。
4. 设置父子关系，全部成功后才让子 Ready。新任务调度级别按既有“新任务”策略初始化。
5. 父子在相同虚拟地址分别写不同标记，再让出或接受抢占，验证互不影响，最后父 wait 子。

前 15 分钟画复制清单，25 分钟实现，15 分钟检查。父先运行还是子先运行由调度决定，不写死输出先后顺序。

## B 次：失败与回收

1. 用小测试页池制造中途失败，回滚已分配子页与表页，清除预留槽，父收到 -4 并继续。
2. 进程容量满时拒绝创建，不能生成可见半成品 PID。
3. 重复 fork→子 exit→父 wait，确认槽位和页数回到基线；分别测试父提前结束和子故障。
4. 第 27 课新增 fd 后，fork 复制 fd 表条目并增加端点引用，不复制管道字节缓冲区；失败也要撤销新增引用。

## 常见问题与验收

| 现象 | 先检查 |
| --- | --- |
| fork 无限创建孩子 | 子是否仍停在原 `ecall` |
| 父子都得到同一返回值 | 是否修改了同一份现场 |
| 父数据被子改变 | 是否只复制页表而没有复制私有物理页 |

- [ ] 父子返回值和后续分支正确。
- [ ] 用户栈与数据独立，进程关系和 wait 可用。
- [ ] 分配失败、容量满与重复生命周期不泄漏。
- [ ] 更新 [进度记录](progress.md)。
