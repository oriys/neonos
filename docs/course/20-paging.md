# 第 20 课：第一次开启分页

状态：待开始。前置：[第 19 课](19-page-tables.md)。分 A、B 两次，每次 45～60 分钟。

## 目标与导读

分页启用后，内核仍能取指、使用栈、打印和报告故障。先停用用户派发和定时源，保留独立构建开关方便回到未分页诊断路径。

## A 次：先做完整映射清单

1. 用第一阶段链接符号列出代码、只读数据、可写数据、全部栈、分配器元数据、堆和 RAM 页池；加入 UART 所在设备页及本内核实际还会访问的设备或固件数据。
2. 建立内核恒等映射：代码 RX、只读数据 R、可写数据与栈 RW，所有这些页 U=0。RAM 空闲页池提供 RW、不可执行的内核访问映射。
3. 以实际页边界分区，避免只读代码页被另一条“整个 RAM 都可写”的映射覆盖；共享边界页需先调整链接布局。
4. 映射正在运行的分页切换指令、当前栈、异常入口、诊断代码以及所有页表页。页表构造完整后用软件查询逐项核对。
5. 本课不需要映射 OpenSBI 的所有私有内存；只映射内核自身实际访问的区域，不根据固件地址猜测可用 RAM。

约 15 分钟列清单、25 分钟建表、15 分钟核对权限。

## B 次：切换并确认

1. 在屏蔽中断的受控路径按 Sv39 要求写入根物理页号和模式；第一版 ASID=0。
2. 按 [RISC-V 规范](https://riscv.github.io/riscv-unified-db/manual/html/isa/isa_20240411/chapters/supervisor.html) 使用 `sfence.vma` 建立所需转换同步，不把写 `satp` 当作自动清除旧转换。
3. 因为切换前后内核地址相同，执行流继续打印 `paging enabled`，再访问可写测试数据、调用辅助函数使用栈。
4. 重新检查软件页表查询，确认根表和分配器可在分页状态下访问。
5. 保留内核故障报告；单独构建负例，撤掉一个专用测试页映射后访问它，验证诊断。不要删掉当前栈或异常入口作为第一种负例。

## 常见问题与验收

| 现象 | 先检查 |
| --- | --- |
| 开启后立即没输出 | 当前代码、栈、UART 与异常入口是否全映射 |
| 页表看起来正确但取指失败 | 页表根物理地址、叶项权限、规范地址与 A 位 |
| 打印可以，分配器失败 | 其元数据、页池和表页是否有内核访问映射 |
