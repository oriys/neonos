# 第 30 课：同一个进程里，运行多条执行路线

状态：待开始。前置：[第 29 课](29-races.md)。分 A、B、C 三次，每次 45～60 分钟。

## 目标与导读

阅读 OSTEP 第 26～27 章。打开已有进程、调度和用户现场代码，把资源所有权与执行状态分开。每次约 15 分钟设计、30 分钟修改、15 分钟验收。

## A 次：按线程调度

1. Process 保留 PID、根页表、fd 和父子关系；Thread 增加 TID、所属 PID、独立现场、用户栈、陷入栈与等待原因。
2. 把 Ready 队列、当前任务和 MLFQ 用量改为按 TID 管理。旧单线程进程创建一个主线程，原功能先保持通过。
3. 同进程线程共享根页表，切换仍需恢复正确现场、陷入栈及 `sscratch`；跨进程继续切换根并同步转换。
4. 线程栈从预留虚拟槽位逐个映射，保持页对齐、调用对齐和保护页，不覆盖原用户区。

## B 次：创建、运行与返回

1. `thread_create(entry,arg)` 验证入口，分配内核管理的用户栈和陷入栈，构造现场，失败完整回滚。
2. 使用已验证的用户启动包装：调用用户入口并传 arg，入口返回后调用 thread_exit；不能让用户 `ret` 跳回内核地址。
3. 两个线程在不同用户栈保存不同哨兵，在公共数据页写不同槽位；先以不竞争的方式证明共享可见，再用明确交错重现第 29 课现象。
4. 用户样例仍是已知整数汇编，内核 Rust 访问共享用户数据采用受控原始复制，不建立跨调度的可变引用。

## C 次：join 与兼容

1. thread_exit 保留最小结束记录；join 成功写回状态后回收该线程记录。栈在安全点不再使用后可释放，根页表由进程持有。
2. 覆盖先结束、后等待、自身 join、重复 join 和两个等待者竞争。状态指针错误不得吞掉结束结果。
3. 按 [阶段约定](stage-06.md) 区分线程退出与整个进程退出，进程故障先取消所有线程和等待记录再释放共享资源。
4. 为多线程 fork/exec、fd 正在使用时的 close/dup2 添加明确 -9；退出路径应先撤销待完成调用再解除这些使用标记。
5. 用户复制在单核内核不可抢占区间完成；待完成调用只保存地址数值，重新进入时检查映射与权限，不持有可失效引用。

## 常见问题与验收

| 现象 | 先检查 |
| --- | --- |
| 第一个线程退出后全进程坏掉 | 是否提前释放共享根页表 |
| 同进程切换后陷入另一个栈 | 当前 TID 与可信栈是否一起更新 |
| 管道重试操作了新 fd | fd 使用中标记与覆盖检查是否遗漏 |

- [ ] 两线程共享数据、独立现场，抢占后哨兵正确。
- [ ] 生命周期、创建失败和重复回收可验证。
- [ ] 原单线程 shell、fork、管道通过，更新 [进度记录](progress.md)。
