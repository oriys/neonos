# 第 11 课：谁先运行，怎么算更好

状态：待开始。前置：[第二阶段](stage-02.md) 验收完成。预计 45～60 分钟。

## 目标与阅读

先在纸上和宿主机模拟调度，不改内核。阅读 [OSTEP 第 7 章 CPU Scheduling](https://pages.cs.wisc.edu/~remzi/OSTEP/)，理解 FCFS（先来先服务）、SJF（短任务优先）和 RR（轮转）。

响应时间 = 第一次得到 CPU 的时刻 − 到达时刻；周转时间 = 完成时刻 − 到达时刻。这里的响应指首次得到 CPU，不是首次打印文字。模拟先忽略切换成本。

## 手算实验（15 分钟）

三任务都在时刻 0 到达，初始顺序 A、B、C，需要的 CPU 时间分别为 6、2、1。SJF 采用非抢占版本；RR 时间片为 2。先画时间线，再对照：

| 策略 | 执行时间线 | 平均响应 | 平均周转 |
| --- | --- | --- | --- |
| FCFS | A:0～6，B:6～8，C:8～9 | 14/3 | 23/3 |
| SJF | C:0～1，B:1～3，A:3～9 | 4/3 | 13/3 |
| RR | A:0～2，B:2～4，C:4～5，A:5～7，A:7～9 | 2 | 6 |

这是课程构造的算例。SJF 此处事先知道任务长度，实际内核一般不知道程序还要执行多久，因此模拟结果不能直接当作可实现的最优承诺。

## 写一个小模拟器（25 分钟）

1. 计划创建 `experiments/scheduling.py`，用 Python 标准库运行于宿主机。记录任务编号、到达、所需 CPU 时间、剩余时间、首次运行和完成时刻。
2. 分开“推进时钟”“处理到达”“选择任务”和“统计结果”，每次输出运行区间及选择原因。
3. 固定同一时刻的顺序：先结算上一段执行和完成，再加入新到达任务，最后把时间片耗尽的未完成任务放回队尾；同刻到达按输入顺序。
4. 空队列时跳到下一次到达；零长度任务在到达时完成，约定响应与周转都为 0；负到达时间、负长度和非正时间片应拒绝。
5. 用上表验证，再把 B 的到达改成 1、C 改成 3，重新预测后运行。

验证 CPU 实际执行总量等于所有任务需求之和；结束时间可以大于执行总量，因为中间可能空闲。

## 常见问题

| 现象 | 先检查 |
| --- | --- |
| RR 的响应时间每次都重算 | 首次运行时刻是否只记录一次 |
| 周转结果不包含等待 | 是否误把执行用量当成完成减到达 |
| 同一输入出现不同顺序 | 同刻事件和平局规则是否固定 |
| 模拟卡在空队列 | 是否跳到了下一次任务到达 |
