# 第 21 课：两个进程，同一个地址，不同的数据

状态：待开始。前置：[第 20 课](20-paging.md)。分 A、B 两次，每次 45～60 分钟；用户代码迁移可额外拆练。

## 目标与设计

每个进程持有独立根页表、私有数据与栈页。按 [阶段设计](stage-04.md) 保留共同的 U=0 内核映射，陷入期间不必先切换到另一根才能访问可信内核栈。

## A 次：准备私有映射

1. 在计划中的 `address_space.rs` 记录根表、拥有的表页和用户数据页。构建失败时回收本次分配资源，不把半成品交给调度器。
2. 分别为用户代码、数据、栈分配并清零物理页，用户权限分别为 RX、RW、RW，栈下保护页不映射。禁止用户可写且可执行的映射。
3. 将内嵌汇编程序和用户调用封装整理成可整体复制的样例：内部代码引用使用 PC 相对方式，不引用内核绝对地址、内核 `gp` 或外部函数；核对反汇编。用户数据通过约定虚拟地址访问。
4. 将这份样例复制到新代码物理页，用户入口是目标虚拟基址加入口偏移，不能沿用原内核入口地址；完成代码写入后按平台要求执行指令同步，例如本地 `fence.i`。
5. 以两个进程的 `0x01000000` 为私有数据页，写不同标记。软件查询确认其物理页不同；用户每次恢复后读取并验证自己的值。

不能把代码与相邻内核数据共用的物理页整体标成 U=1。内核仍通过自身 U=0 映射访问和复制物理页，用户映射不提供内核入口执行权。

## B 次：接入调度与回收

1. 派发用户前选中目标根，写入地址空间上下文并完成本地转换同步，再恢复用户现场。
2. 所有根中的内核调度栈、陷入入口和可信元数据地址必须一致且可用；`sscratch` 始终记录可信内核地址。
3. 先关闭定时源做主动让出切换，再恢复 RR 定时抢占；各运行 100 次检查，验证私有标记和栈内容不变。
4. 退出或 Faulted 后先回调度栈，切换到保留的内核根并同步；确认没有硬件仍使用该根，再回收进程拥有的页。
5. 内核公共代码、UART 等映射目标不由进程释放；相同物理地址被多个根映射不代表每个根都拥有它。
6. 重复创建与结束固定测试实例，比较页数；页表根、下级表和用户页都要计入，允许长期内核资源保持占用。

## 常见问题与验收

| 现象 | 先检查 |
| --- | --- |
| 切换后读到上一进程数据 | 是否切换根并同步，是否误用了相同私有物理页 |
| 用户跳到内核地址 | 入口或代码内引用是否仍是旧地址 |
| 退出一个进程其他进程崩溃 | 是否释放了共享内核映射目标或当前仍在使用的根 |

- [ ] 相同用户虚拟地址映射不同物理页，抢占后数据正确。
- [ ] 内核映射均为 U=0，代码和栈权限符合规划。
- [ ] 创建失败回滚、退出回收与重复运行无页数泄漏。
- [ ] 原用户接口、RR 和 MLFQ 场景回归，更新 [进度记录](progress.md)。

小练习：说明切换了寄存器却没切换页表，为什么仍不能实现进程内存隔离。
