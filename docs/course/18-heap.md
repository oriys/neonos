# 第 18 课：页里面的小对象怎么分配

状态：待开始。前置：[第 17 课](17-frames.md)。分 A、B 两次，每次 45～60 分钟。

## 目标与阅读

阅读 OSTEP 第 14、17 章。用独立预留 arena 实现支持分配和释放的小堆，认识对齐与外部碎片。分配接口先显式调用，不急着让整个内核依赖全局分配器。

## A 次：按大小与对齐分配

1. 静态预留例如 64 KiB arena，并从物理页可用清单排除；设置固定容量空闲区间表和已分配记录表，不把堆元数据再放进堆分配。
2. 使用 first-fit 查找能容纳请求的空闲区间，计算满足对齐的开始地址，检查大小、对齐和末尾计算。
3. 明确零大小请求的本课行为为拒绝；对齐必须是正的二次幂。返回起始地址及句柄，调用者只能写申请范围。
4. 分配后记录前缀空隙和剩余尾部，不能把对齐留下的字节永久丢失。
5. 元数据容量不足与内存不足一样是可预期失败，失败不能先删掉原空闲区间再遗失它。

约 15 分钟图解、25 分钟实现、15 分钟核对。测试 1、24、4096 字节及多种对齐，在分配范围内写不同模式验证不重叠。

## B 次：释放和合并

1. 按有效句柄释放，拒绝重复释放和无效句柄；本课为便于诊断，额外保存分配记录。
2. 空闲区间按地址排序，只合并真正相邻的区间；分配间隙不能凭空消失。
3. 依次申请 A、B、C，释放 B 后申请较小对象；再释放全部，确认 arena 恢复为一个大空闲区间。
4. 构造总空闲字节够、最大连续空闲块不够的请求，解释为何仍分配失败。
5. 再运行原物理页检查，确认两套分配器不管理同一片内存。

以后接入 [Rust GlobalAlloc](https://doc.rust-lang.org/core/alloc/trait.GlobalAlloc.html) 时需按其接口和安全契约适配：当前诊断句柄接口不能直接当成全局分配器。分配器内部不要通过堆分配或递归格式化报告错误。

## 常见问题与验收

| 现象 | 先检查 |
| --- | --- |
| 地址不满足对齐 | 是否只对大小取整，没有对起始地址对齐 |
| 释放全部仍缺少空间 | 对齐前缀或分割元数据是否丢失 |
| 总空闲很多但申请失败 | 最大连续区间和元数据容量是否足够 |

- [ ] 不同大小与对齐正确，分配互不重叠。
- [ ] 分割、合并、耗尽与元数据不足都有明确结果。
- [ ] 能解释固定页分配与对象堆分配的不同用途。
